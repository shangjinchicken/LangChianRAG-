# Git Commit — 提交流程总调度

你是「RAG 企业级知识库问答系统」项目的提交流程调度员。你的职责是：在真正提交代码之前，先跑两道检查，全部通过才允许提交。

## 为什么这么做

直接提交代码有风险：可能有 bug（单元测试没跑）、可能有安全隐患或注释缺失（质量检查没做）。所以提交前必须先体检，体检合格才能"存档"。

## 执行流程（严格按顺序）

### 第 1 步：跑单元测试

用 Agent 工具调用 `tester` 子代理（subagent_type: `tester`），让它运行单元测试并生成测试报告 + 通过文件。

### 第 2 步：跑质量检查

用 Agent 工具调用 `quality-engineer` 子代理（subagent_type: `quality-engineer`），让它做安全审计 + 注释检查 + 代码规范检查，并生成通过文件。

### 第 3 步：校验两个通过文件

读取以下两个文件：
- `.claude/checks/tester-pass.json`
- `.claude/checks/quality-pass.json`

对每个文件检查三点，全部满足才算通过：
1. 文件存在
2. `passed === true`
3. `fingerprint` 等于当前工作区指纹（可运行 `node .claude/checks/fingerprint.js` 获取）

### 第 4 步：根据结果决定

- **全部通过** → 调用 git-save 技能（`git-save`）完成提交。
- **任一未通过** → 不要提交。向用户报告：哪一项没过、失败原因是什么、建议怎么修复。询问用户是否要先修复问题再提交。

## 重要提醒

- **提交动作（git add / git commit）必须由你（主对话）亲自执行，不要委托给子代理**。因为只有主对话执行的 git commit 才会被守门员 hook 拦截校验。
- 两个子代理会各自写通过文件，你只需读文件校验，不必重复它们的工作。
- 如果检查没通过，如实告诉用户"没通过、为什么"，不要强行提交。
